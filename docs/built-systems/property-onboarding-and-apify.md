# Property Onboarding & Apify Ingestion — Rules

Canonical sources: `src/lib/apify-crawler.ts` (ingestion), `src/lib/kb-extractor.ts` (synthesis), `src/components/dashboard/onboarding/` (UI), `src/app/api/onboarding/`.

---

## Rules

- **Never fabricate property facts.** The knowledge-base synthesizer operates under a strict fact-vs-copy split: marketing copy may be written, but specs, lease terms, and policies may only be restated from crawled or spoken input. Inventing an unstated term is the worst failure mode in this system — it puts false claims into a sales agent's mouth. The same rule applies to the UI: the review card renders "Not specified" for a missing term; never substitute a plausible default such as "No HOA fee" or "Available immediately".
- **Never block Agora WebRTC voice turns on LLM extraction.** Turn-level extraction runs asynchronously out-of-band using Gemini with an attention scratchpad (`spokenSummary`) and required nullable core schema. It dispatches immediately upon user turn completion (`isUser && isFinished`) to extract in parallel while Elena begins speaking, as well as upon agent turn completion (`isSpeaking: false`). Requests are managed via a **Trailing Conflating Queue**: in-flight requests are never hard-aborted; fast subsequent turns coalesce into a single follow-up call once the active extraction completes. The WebRTC voice audio stream flows continuously with zero interruption or audio latency. Continuous listening stays active throughout the call to capture verbal corrections.
- **Never feed the extractor user-only transcripts.** Always include labeled assistant turns (`[ELENA VANCE]` and `[OWNER]`) so the model can repair ASR speech-to-text phonetic slips from question and confirmation context — and never let assistant text be treated as owner facts.
- **Never let end-of-call synthesis clobber live verified attributes.** Live verified specs on screen are immutable ground truth; post-call synthesis enriches descriptions, sales pitches, FAQs, and negotiation rules, but must never overwrite verified specs with empty or ungrounded values.
- **Never pre-fill the inspector pane with empty form fields.** Parameters are revealed only as they are genuinely detected. The design intent is that visible state always reflects real extracted data, so an owner can trust the checklist.
- **The deploy action stays locked until every required attribute is verified.** Do not add a bypass.
- **"Core specs verified" has one definition: `getCoreSpecStatus` in `src/components/dashboard/onboarding/inspector-specs.ts`.** The checklist, the deploy lock, the studio's review-card gate, the review card, and the end-of-call merge all consume it. A bedroom count of 0 is verified only when the title or description says "studio"; a bare 0 is an unstated count. Never re-derive the rule in a component: three copies once disagreed, and the review card could open with bedrooms unknown.
- **Never trigger the Review Specs modal via automatic 6/6 thresholding or synthetic RTM text injection.** Modal presentation is strictly conversational or user-driven (via Elena's verbal completion cues, explicit owner voice commands like "pull up / show the review card", or manual UI clicks). The UI coordinates via an **In-Flight Sync Gate**: because user-turn extraction runs in parallel while Elena speaks, all 6 specs typically land before Elena reaches her review card announcement. If Elena or the owner requests opening the review modal while an extraction is still resolving in the trailing conflating queue, the UI latches the open request (`pendingModalOpenRef`) until the in-flight extraction lands in state. This guarantees Gemini has populated all remaining blanks (e.g. beds, baths, sqft stated in the final utterance) before the card renders. **Injecting synthetic RTM user messages mid-call is strictly banned**: it causes Elena to read bracketed prompt cues aloud, aborts ongoing speech playback, and creates conflicting turn states that cause Google Gemini to reject requests with `400: Requests ending with a model turn are not supported`.
- **Apify runs in strict mode**: a missing token or a failed crawl throws immediately rather than returning partial data. Preserve that — see the fail-fast contract in [voice-agent-and-agora.md](voice-agent-and-agora.md).
- **Gemini is the only synthesizer. Never add an offline, regex, or heuristic fallback.** When Gemini is unconfigured, unreachable, or returns nothing, `extractPropertyKnowledgeBase` throws and the studio shows the error beside the transcript. The heuristic that once stood in for it silently produced thinner, unverified knowledge bases with no error, which the fail-fast contract forbids.
- **Owner identity is pre-authenticated**: Elena Vance must always address the owner by their account first name (using strict fallback `"Hello there!"` if the display name is blank) and weave in a confirmation of their account email for public listing inquiries, rather than treating the owner as an anonymous caller.
- **Two-tier onboarding flow**: Elena Vance verifies the 6 core specifications first and opens the Core Specs review card. Additional property specs (parking, utilities, HOA, availability) are gathered only after the owner confirms the core specs.
- **Never ask home sellers for a universal pet policy**: Pet policies are strictly rental-specific; asking a seller for a pet policy on a single-family home violates natural real estate conventions. On sales, pet bylaws are scoped strictly to condo/co-op HOA inquiries.
- **Never use viewport-level `scrollIntoView()` for live transcripts**: Transcript auto-scrolling must stay strictly confined to internal container `.scrollTo()` to prevent ancestor scrolling from pushing sticky call controls (Elena Vance's avatar, status, and the Disconnect button) out of the viewport.
- **Listing type is permanently locked once established**: In Stage 1, once `listingType` ("rent" vs "sale") is chosen, it cannot be changed verbally later in the session because the entire subsequent dialogue structure and intake questions branch directly on it. All other specs remain continuously editable.
- **Assistant turn intent deduplication policy**: Each assistant turn intent must be keyed (`assistant_${turnId}_${intent}`) so an assistant announcement fires only once per turn. Evaluating un-deduplicated historic assistant transcripts re-triggers past intents across stages and is strictly prohibited.
- **Strict Stage Isolation for Review Modals**: Core specs announcements (`open_core_modal`) must never trigger the Final Review modal; Final Review announcements (`open_final_modal`) must be ignored if the session is still in Stage 1 (`core`).
- **Final Review Modal must enforce the In-Flight Sync Gate**: If Elena announces opening the final review card while a voice turn extraction is currently in-flight OR before `availableDate` has landed in state, the modal presentation must be latched (`pendingFinalModalOpenRef`) until the in-flight extraction completes. Never render the review card prematurely with newly spoken attributes showing as "Not specified". The gate auto-releases after a 2,500ms safety threshold so the UI never hangs.
- **Coalesced Retry Buffer & Silent Abort Handling**: Live turn extraction requests enforce a 15-second client abort timeout. If an extraction times out or fails, failed turns are buffered and coalesced with subsequent turns so no spoken facts or numbers are lost. `AbortError` must be handled cleanly without logging to `console.error`, preventing Next.js Turbopack dev error overlays.
- **Dynamic AI Pills & Zero-False-Positive Matching in Suggestion Bar**: Custom user choices (e.g. "3-Car Parking", "In 15 Days") must be prepended dynamically with active styling and concise AI badge labels, trimming 1-2 prebuilt options to maintain layout balance. First-word substring matching (`split(" ")[0]`) is strictly banned to prevent false-positive highlights (such as "No Pets" or "No Parking").
- **Two-Step Self-Verifying Post-Call Audit**: End-of-call full-transcript synthesis passes both the complete dialogue and the current live verified state. If discrepancies or contradictions are detected between the live inspector state and the transcript, a 2nd targeted verification pass executes to resolve ground truth and rectify the fields.
- **Telemetry HUD**: Provides full session observability across Agora transcripts, intent triggers, sync gate states, and API latencies with a toggle for dev and production modes.
- **Multi-Device Photo Uplink & Draft Persistence**: Confirming additional specs creates a `status: 'draft'` property record and generates an `uploadToken` with a vector QR code. The mobile upload page (`/properties/upload/[id]`) authenticates via this token without requiring mobile login. The desktop Image Upload Modal short-polls (`/api/properties/draft/[id]/images`) every 2.5 seconds to display incoming photos live. Final deployment activates the draft into `status: 'active'`, preserving all linked media.
